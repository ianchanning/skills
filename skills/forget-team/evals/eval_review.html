How the Skill Creator & Eval Viewer Work

This viewer is generated by ~/.agents/skills/skill-creator/eval-viewer/generate_review.py to evaluate and iterate on GitHub Copilot CLI skills using controlled A/B subagent runs.

1. Skill Folder vs. Workspace Folder (<skill> vs. <skill>-workspace)

When benchmarking a skill, two sibling folders exist in ~/.agents/skills/:

  • ~/.agents/skills/<skill-name>/ (The Live Skill): Contains SKILL.md, helper scripts in scripts/, and test prompts in evals/evals.json. This is what GitHub Copilot CLI loads in future sessions.
  • ~/.agents/skills/<skill-name>-workspace/ (The Benchmark Scratchpad): Contains iteration-1/, iteration-2/, subagent outputs (response.md), assertion grades (grading.json), summary stats (benchmark.json), and this eval_review.html file. It is not a skill (no SKILL.md) and can be deleted or moved to /tmp once you are happy with the skill.
2. How Outputs & Benchmark Scores Are Generated
  1. Parallel A/B Subagent Runs (with_skill vs. without_skill): For each test case in evals/evals.json, GitHub Copilot CLI launches two isolated subagents in parallel: one given access to the new SKILL.md (with_skill) and a baseline agent without the skill (without_skill, or old_skill when upgrading an existing skill). Each writes its answer to outputs/response.md.
  2. Semantic & Programmatic Grading (grading.json): Each run is evaluated against the objective assertions defined in eval_metadata.json. Every assertion is scored ✓ Passed or ✗ Failed with cited evidence from the subagent output (visible under Formal Grades in the Outputs tab and in the per-eval tables in the Benchmark tab).
  3. Aggregation (benchmark.json): scripts/aggregate_benchmark.py computes the mean ± stddev pass rate, runtime, and delta between with_skill and without_skill.
3. What “Submit All Reviews” Does & How Iteration Works
  • Where does “Submit All Reviews” go? Nowhere over the network. When opened as a standalone file (--static mode), clicking Submit All Reviews triggers a local browser download of ~/Downloads/feedback.json containing any notes you typed into the Your Feedback boxes (or posts to localhost if launched in local server mode).
  • How does your feedback affect scores? Your feedback does not retroactively alter iteration-1 scores. Instead, when you tell GitHub Copilot CLI that you have submitted feedback, it starts iteration-2:
    1. Reads ~/Downloads/feedback.json and updates SKILL.md (and bundled scripts/) to address your critiques.
    2. If your feedback highlights a missing requirement that the assertions didn't catch, adds or refines assertions in evals/evals.json.
    3. Spawns fresh subagents into iteration-2/, grades the new outputs against the updated rubric, and regenerates this viewer with Previous Output and Previous Feedback diffs so you can verify the improvement.
  • What if everything already looks good? If iteration-1 is already at 100% and you like the outputs, you don't need to submit anything — the skill in ~/.agents/skills/<skill-name>/ is ready to use immediately.
